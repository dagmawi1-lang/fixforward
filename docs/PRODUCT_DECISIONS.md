# FixForward — product decisions and judging alignment

## Primary user
A neighbor or student who notices a maintenance issue in a shared public space and wants to describe it clearly.

## Single most important outcome
Organize public-space observations into a searchable board with transparent prioritization and status tracking.

## Prototype success measure
A user can submit an observation, support it, and export a structured board.

## Scope guardrail
No emergency dispatch, municipal integration, verified identity, or secure one-person-one-vote claim.

## Judging narrative
- **Problem clarity:** open with the specific user and friction above, not a broad claim that the app solves an entire sector.
- **Originality:** demonstrate the project-specific workflow and the reason it is useful, not just a generic dashboard or AI wrapper.
- **Execution:** complete one polished end-to-end workflow before adding integrations.
- **Impact:** report only prototype measurements that were actually collected. Do not invent users, adoption, outcomes, or partnerships.
- **Communication:** show one realistic example, explain one technical decision, and state one limitation honestly.

## Feature priority
1. Core workflow reliability.
2. Clear explanations and accessible interaction.
3. Data validation and useful empty/error states.
4. Export or share capability if it supports the main workflow.
5. Optional integrations only after the local fallback works.
